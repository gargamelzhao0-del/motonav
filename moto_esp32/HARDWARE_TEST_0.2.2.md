# 0.2.2 局部地图性能验证

2026-11-12，在用户确认的 COM21 / Waveshare ESP32-S3-Touch-AMOLED-1.75C 上测试。ESP32-S3 rev 0.2、32 MB Flash、8 MB OPI PSRAM，ESP-IDF 5.5.4、BSP 3.0.0、LVGL 9.5.0。保持 QSPI 40 MHz、CPU 240 MHz、两块 50 行内部 RAM 绘制缓冲，LVGL 在 CPU1、BLE 在 CPU0。

## 本次实现

- 增加 `ROUTE MAP / SIMULATED` 性能页：320 × 300 RGB565 地图，路线、道路、方向标记随相机平移和旋转；页面明确标注 `DISPLAY TEST / NOT NAVIGATION`。
- 地图使用有界坐标投影、绘制前线段裁剪和直接 RGB565 扫描线绘制，避免为每条地图线建立 LVGL 绘制任务。地图几何不做抗锯齿；文字仍由 LVGL 绘制。
- 列范围相同且行连续的局部条带使用 CO5300 RAMWRC；列变化、间断或提交失败会重新设定地址。完成计数仍由实际末块 DMA 回调提供。
- 手动短触切换局部 HUD、全屏重绘、地图三种负载；长按退出。配对请求或有效导航会退出地图并释放其缓冲。
- 修正自动切换负载时的时间采样顺序：切换后重新读取单调时钟，避免无符号时间差下溢，把刚清零的 FPS 错记为一次最低 0。主机测试通过模拟切换跨越毫秒边界覆盖此问题。

NAV3 字节协议、真实导航来源校验、时效及断线处理没有改变。地图性能页的几何是独立模拟样本，尚未接收手机路线。

## 最终实测

通过 `tools/build.ps1 -DisplayBench -BenchSeconds 123` 构建测试镜像。每种负载总计约 123 秒，其中前 2.5 秒预热；串口记录完整三项测试及退出后的状态。BLE 处于广播状态，无手机导航流量。

| 负载 | 采样最低 FPS | 采样平均 FPS | 样本数 | 预热后测量时间 |
| --- | ---: | ---: | ---: | ---: |
| 局部 HUD | 59 | 60 | 108 | 120,500 ms |
| 强制全屏重绘 | 31 | 31 | 107 | 120,504 ms |
| 320 × 300 动态地图 | 41 | 42 | 108 | 120,511 ms |

地图样本含 7 个路线点、22 条背景道路线段及方向标记。测量区间内调用地图绘制 5,168 次，平均绘制耗时 7,929 μs、最大 8,606 μs；这些是地图生成耗时，不是完整显示帧时长。地图运行时总空闲堆稳定在 7,800,284 字节、内部空闲堆 82,719 字节；退出后分别恢复到 7,993,160 与 83,079 字节。日志未见 panic 或 watchdog。

FPS 每约 1.1 秒读取一次，平均值为采样 FPS 的整数均值，最低值是采样窗口最低值；不是逐帧延迟的严格上界。动态地图样本达到此次 40 FPS 目标，全屏重绘仍未达到。不能把此结果外推为 512 点上限、任意道路密度、透视底图、中文文字叠加或手机持续传输时的帧率保证。

最终日志：`dist/COM21-0.2.2-map/serial-regression-final.log`；测试镜像：同目录 `motonav-regression-final.bin`。此前 `serial-regression.log` 中包含切换统计问题，保留用于诊断，不作为最终验收数据。

## 优化过程

相同地图样本每轮约 40.5 秒的初步测量：

| 实现阶段 | 最低 / 平均 FPS | 地图绘制平均耗时 |
| --- | ---: | ---: |
| LVGL Canvas 绘制任务 | 14 / 16 | 41,671 μs |
| 有界 RGB565 扫描线绘制 | 38 / 39 | 9,598 μs |
| 加入局部连续条带传输 | 38 / 39 | 9,542 μs |
| 缓存行复制与扫描线取整优化 | 41 / 42 | 7,954 μs |

不能把性能提升单独归因于连续条带：本机主要收益来自地图绘制路径。最终采用上述实现组合，并完成两分钟/负载回归。
