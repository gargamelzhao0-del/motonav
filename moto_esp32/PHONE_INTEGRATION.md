# 手机与圆屏 NAV4 联调

集成版本：ESP32 0.3.2、Android 0.7.9/0.7.10。COM21 对应 `MotoNav-51CA`。0.3.1 合并 0.2.7 的 RGB332 显示驱动和 NAV4 正式路线输入，0.3.2 修正 Android 蓝牙指示确认和旧订阅抢占通道；NAV3 箭头导航继续兼容。显示驱动实测记录属于 0.2.7 模拟负载，不能代替本版本的真实导航联调。

## 手机操作

1. 打开 App 的真实地图页，确认地图配置、精确定位权限和系统定位可用。
2. 在「圆屏设备」点击连接并选择 `MotoNav-51CA`；若出现系统配对窗口，输入圆屏显示的六位码，保留前导零。已有配对无需主动删除。
3. 等待圆屏进入 `READY FOR ROUTE`。App 发现 NAV4 服务后自动选择路线地图协议，不需要手动选择版本。
4. 在停车状态选择目的地并点击开始。获得可信位置和真实导航指令后，圆屏显示路线、位置箭头、转向、距离、速度和剩余行程；无可用路线窗口时显示箭头视图。
5. 手机锁屏后保持两分钟，随后结束导航，核对持续更新与结束清屏。

普通汽车驾车路线不含摩托车禁限行避让。SDK 模拟导航目前不发送 NAV4；不要把模拟定位或室内低精度位置当成真实导航输入。

## 设备证据

常规日志每 5 秒记录：`state/link/secure/protocol/route_points/route_revision/rx/dup/rejected/heap/internal`，不打印位置坐标、PIN 或道路名称。

| 情况 | 日志及画面 |
| --- | --- |
| NAV4 订阅和握手成功 | `protocol=4`，`link=1 secure=1`，接收计数增长 |
| 有效路线地图 | `state=7 route_points>=2`，地图及诱导一起更新 |
| NAV3 兼容模式 | `protocol=3 route_points=0`，显示箭头导航 |
| 等待真实指令 | `state=5`，隐藏旧地图和数字 |
| 数据失效 | `state=6`，4 秒断流或来源年龄超限后隐藏旧诱导 |
| 到达／主动结束 | `state=8/9`，不再显示旧转向 |
| 断连后恢复 | 重新加密、订阅、握手，接受当前会话的新快照 |

如果升级后仍协商 NAV3，先在 App 断开再重新连接，让手机重新发现服务；仅当手机仍保留旧服务缓存时再考虑系统重新配对。

## 被动帧率采样

```powershell
pwsh -File tools/build.ps1 -NavigationMetrics
python tools/capture_serial.py --port COM21 --seconds 240 --output dist/phone-integration/serial.log
```

`NavigationMetrics` 只观察真实输入，不内置模拟路线、不解除认证、不向会话注入数据；不能与显示测试同时启用。它约每 1.1 秒采样，地图进入有效状态后预热 2.5 秒，再输出 `navigation_perf`。`last_render_fps` 来自最后一块像素 DMA 完成计数，`motion` 只表示相邻快照的位置／航向发生变化，不记录坐标。

该诊断构建也通过 ESP-IDF 5.5 的 `ble_att_tx` 链接包装记录五字节 ATT 错误头（请求操作、属性句柄、错误码），不记录其他报文内容。正常构建不编入该包装。常规固件保留安全状态、订阅事件与最终协议选择日志，均不包含配对码与坐标。

静止画面不会强制重绘，低刷新数不等于性能不足。采样值是最近一次绘制窗口，持续运动时的连续样本才用于评估 40 FPS；手机停止更新、等待定位与显示静止时须分开统计。真实 BLE、路线复杂度及触摸并发需要分别记录，不能用 0.2.7 的模拟地图帧率作保证。

无参数 `tools/build.ps1` 关闭该采样开关，生成正常版。普通串口采集不复位设备；手机联调时不要添加 `--reset-usb`。
