# 手机与圆屏 NAV3 联调

设备为 COM21 对应的 `MotoNav-51CA`。0.2.2 继续使用 [APP_PROTOCOL.md](APP_PROTOCOL.md) 中的 NAV3，地图性能页只使用明确标记的模拟几何，不接收真实路线。App 源码目前核对到 0.7.4；实际手机安装版本须在 App 设置核对。

## 准备

- 使用支持 NAV3 的 App，确认蓝牙和精确位置权限、高德配置正常。
- 在停车状态和能够获得可信定位的环境测试。室内显示等待定位是可能的正常结果，不能用 550 米精度的位置代替有效导航。
- 固件回到 `CONNECT PHONE` 后开始配对。若处于性能页，可长按退出；配对请求或有效导航也会自动退出测试。
- 手机端选择 `MotoNav-51CA`，在系统配对框输入圆屏显示的六位 PIN，保留前导零。不要把 PIN 或地图 Key 写入日志。

## 联调项目

| 操作 | 圆屏和日志应表现为 |
| --- | --- |
| 首次连接、PIN 配对、订阅并握手 | 依次显示连接/配对/等待路线；`link=1 secure=1`，HELLO 使接收计数增加 |
| 手机规划真实路线并启动导航 | 手机和圆屏的转向、距离、速度一致；未知速度显示 `--`；日志出现 `state=7`（有效导航），`rx` 持续增加 |
| 锁屏或切换 App 至少两分钟 | 导航服务保持运行，圆屏持续接收；不依赖地图页面停留在前台 |
| 停止新导航快照或失去可信来源 | 严格遵守原有 4 秒流超时及来源年龄，隐藏失效指令；不能继续显示旧箭头为有效导航 |
| 关闭手机蓝牙后重新开启 | 断开时清除有效诱导；App 重连、重新订阅/握手后恢复当前有效会话 |
| 结束导航 | 进入结束状态，不再显示旧距离；正常结束与意外断开分开记录 |
| 有效导航到来时设备正在地图测试页 | 测试立即结束，模拟画面完全退出，真实导航接管 |

固定状态编号来自 `display_model.h`：0 未连接、1 PIN 配对、2 链路加密中、3 握手、4 等待路线、5 等待有效诱导、6 数据过期、7 有效导航、8 到达、9 结束。

## 有界日志

```powershell
python tools/capture_serial.py --port COM21 --seconds 180 --output dist/phone-integration/serial.log
```

输出路径须尚不存在。普通采集不复位设备；开始手机配对后不要添加 `--reset-usb`。日志中的 `rx/dup/rejected`、`link/secure`、状态和堆余量可以定位协议问题，但没有真实手机操作及屏幕对照时，不能把协议单元测试或电脑版本读取记作手机导航验收通过。

地图收到真实路线的功能须等扩展协议及 App 路线快照接入；当前试验仅验证本地地图绘制性能，NAV3 仍显示箭头导航。
