# 无有效 GPS 时保留路线：0.7.15 / 0.3.6

## 原因

手机 0.7.14 的蓝牙诊断在室内联调中报告 `gps_weak`、源状态和编码状态均为 `WAITING`、地图点数为零。原实现存在两处耦合：`JourneyController.deviceMap()` 仅在 LIVE 时导出几何，NAV4 类型 2 在非 LIVE 状态必须清空位置/路线字段；固件 `RouteReceiver.scene()` 和 UI 同样仅在 LIVE 时显示地图。因此，即使手机已经规划了真实路线，弱 GPS 也会让圆屏只剩等待文字。已恢复的 DIAG1 链路用于证明此状态，不是地图显示修复本身。

GPS 弱可以阻止实时位置与诱导，不能作为删除已规划路线的依据。底图瓦片、周边街道和建筑尚未接入；本轮修复的是已规划路线几何的显示。

## 实现

源提交 `3b90b4f76eeaab3adcbf2f856ce18c95055f966a`。Android 0.7.15（versionCode 23）与固件 0.3.6 使用现有服务协商 NAV4P，新增独立计划报文，不改变旧 NAV3/NAV4 快照格式或 GATT 表。手机缓存实际 SDK 路线总览，圆屏分别存储计划与实时窗口；计划报文不刷新定位、指令或心跳计时。

GPS 弱、等待指令或指引过期时显示全屏总览与状态，不显示车辆位置、速度或转向距离。有效位置和指令恢复后自动切换实时跟随；结束、到达、断线、撤销订阅或加密失效时清除计划。绘制接口通过 `MapGeometry.show_position` 控制位置标记，驱动无需感知导航状态，测试仍位于独立 tests 目录。

## 实机验收边界

2026-11-16 16:03，实际手机已更新到 versionCode 23 并连接 MotoNav-51CA。串口确认 `route_points=17`、`route_revision=1`、`state=5`、接收拒绝为零；诊断持续为 `gps_weak / WAITING`。用户确认完整路线可见。这验证了弱 GPS 下真实路线的独立传输及显示，没有验证完整地图界面。

用户进一步指出：屏幕只有路线和上下简单文字，完全不符合 `sim/index.html` 的效果。此反馈属实；0.3.6 不能作为原型主界面完成交付。开阔室外实时定位、道路诱导与本轮蓝牙并发帧率仍未实测。

## 与模拟器的实际差距

| 图层 | 模拟器实现 | 0.3.6 正式固件 |
| --- | --- | --- |
| 周边环境 | `drawWorld()` 绘制分级道路、建筑、水域、公园；数据来自脚本生成的虚构世界 | `navigation_ui.cpp` 调用 `render_route_map()` 时传入 `roads=nullptr, road_count=0`，只有真实路线和纯色背景 |
| 顶部导航卡 | 箭头区域、距离主数字、路名、临近转向进度 | 简化文字及箭头，无路名输入 |
| 底部仪表 | 大车速、预计到达时间、剩余距离、限速牌 | 仅 LIVE 时显示简化车速/距离/用时；总览没有规划距离/用时字段 |
| 外圈 | 罗盘刻度、方位、速度弧、行程进度弧 | 地图覆盖旧仪表背景后没有对应外圈组件 |
| 地图视角 | 俯视与受限透视切换、道路与 POI 分层 | 二维路线跟随或整段路线适配 |

下一阶段验收以原型地图主屏为基准：完整视觉布局、真实底图输入、独立的数据有效性、真实导航及至少 40 FPS 分别验收。不能以路线点数非零替代地图效果验收，也不能将原型随机生成的道路或数值用于真实导航。规划总距离和预计总用时不依赖当前 GPS，后续应单独传输并标明规划信息；缺少实时速度/转向时保留仪表布局和未知状态。
