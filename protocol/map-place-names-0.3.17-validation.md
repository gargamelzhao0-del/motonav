# 0.7.26 / 0.3.17 周边名称与标注布局

## 问题与实现

陆肖站固定公开底图包含 320 个图元和 12 个选中标注，部分具体小区名不在当前 Shortbread 源图层中。对同一区域 OpenFreeMap/OpenMapTiles 的独立核对也没有证明能补齐这些小区。因此本次保留 OSM 几何，使用 App 已有的高德 PoiSearchV2 官方 SDK 搜索当前区域的名称；没有在生产代码中硬编码测试地名或坐标。

`NearbyPlacesLoader` 独立单线程执行 3 组附近分类搜索，每组最多 25 条、范围 1000 米，60 秒限频，静止 5 分钟或移动 300 米刷新；失败返回错误码，旧结果最长保留 15 分钟。结果只在当前导航内存中保存。取消、结束导航和关闭服务均以 epoch 拒绝迟到结果。坐标直接使用 SDK 的 GCJ-02，与导航路线相同，不重复偏移。`NearbyPlacesState` 管理期限和容量，`MapSceneComposer` 独立管理最终场景代次，避免底图与名称异步完成时互相覆盖。

NAV4S7 扩展名称来源，完整分块接收后一次发布。未协商的旧圆屏仅接收原有 OSM 标注。几何仍为 384、名称仍为 24；源目录最多 75 条，经过视野和类别分配后发送。App 统计分别显示底图原有名称、补充名称、最终圆屏确认数，三者含义不同。

圆屏继续使用原字体、透明描边缓存和抗锯齿图标。名称预算从 6 增为 8，区域名由 1 增为 3、地标名由 2 增为 4；图标受挡时文字可以独立放置，通用图标在具体名称之后分配。最多 8 个候选位置，保留原 350 ms 排版滞回及路线、车标、HUD 避让。临近转向预算为 5，立即转向为 2。按实际已接收的来源显示 OSM/高德署名，驱动配置保持不变。

## 验证范围

- Java 纯逻辑覆盖坐标、名称类别、去重、范围、75 条上限、移动刷新、限频、独立失效时间、旧协议回退和异步场景合成。
- 真实 `NearbyPlacesLoader` 配合 SDK 边界替身：后台查询、取消后不继续请求、迟到结果丢弃、部分失败、错误码、关闭后不能重启 SDK；不访问真实服务。
- Java 生成 S7 帧进入真实 C++ 接收器，验证来源非法值、分块来源不一致、事务发布、STOP 和 S6 回退；BLE 测试同时覆盖 S5/S6/S7 的分块与 ACK 顺序。
- LVGL 原生测试包括三个区域名同时可见、路线上的地铁站图标受挡但名称可见、署名切换、原导航/定位/地图测试。合成标注仅存在测试目录。
- Android 实际 SDK 编译和 lint、正式固件无测试代码检查、CI 与发布校验结果在交付时记录于本地 dist。

真实手机的 Key 权限和附近搜索结果需要安装新版后验证。开发机没有用户的 Key，本地测试不代表陆肖站真实高德名称已返回。室内定位误差会影响查询中心；名称补充不会把粗定位变成精确定位。此版本没有帧率提升结论，上一版陆肖固定场景实测最低/平均约 21 FPS，40 FPS 目标仍未达成。

参考：[高德官方 POI 搜索](https://lbs.amap.com/api/android-sdk/guide/map-data/poi/)、[PoiSearchV2 API](https://a.amap.com/lbs/static/unzip/Android_Map_Doc/Search/com/amap/api/services/poisearch/PoiSearchV2.html)。
